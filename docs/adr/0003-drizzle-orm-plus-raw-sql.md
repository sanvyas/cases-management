# ADR-0003: Drizzle ORM Plus Raw SQL

## Status
Accepted

## Context
We need an ORM or query builder for TypeScript that supports PostgreSQL features we depend on: RLS session variables (`SET LOCAL`), PostGIS, ltree, array types, complex joins, and raw SQL escape hatches for performance-critical queries.

Options considered:
1. **Prisma** — popular, good DX, but limited raw SQL support, no `SET LOCAL` lifecycle control, schema-first approach conflicts with our migration strategy.
2. **TypeORM** — mature but heavy, decorator-based, weaker TypeScript inference, migration story is fragile.
3. **Drizzle ORM** — lightweight, SQL-like API with strong TypeScript inference, supports raw SQL, explicit transaction control, and schema defined in TypeScript.
4. **Raw SQL only (e.g. pg + slonik)** — maximum control but no type-safe schema, more boilerplate.

## Decision
We use **Drizzle ORM** for schema definition, migrations, and standard CRUD. We use **raw SQL** (via Drizzle's `sql` template tag or direct `pg` queries) for:
- RLS setup (`SET LOCAL` statements)
- Complex reporting queries
- PostGIS spatial queries
- ltree operations
- Performance-critical paths where the ORM's SQL is suboptimal

Schema is defined in `packages/db/schema/` using Drizzle's TypeScript schema builder. Migrations are generated by Drizzle Kit and stored in `packages/db/migrations/`.

## Consequences
- **Type safety:** Drizzle infers TypeScript types from the schema, reducing runtime type mismatches.
- **Migration control:** Drizzle Kit generates SQL migrations that we review and commit. Forward-only; expand/migrate/contract pattern for destructive changes.
- **Learning curve:** developers must know both the Drizzle API and raw SQL. The boundary of when to use which is documented in contributing guidelines.
- **Raw SQL risk:** raw SQL bypasses some type safety. We mitigate with parameterised queries only (never string interpolation) and integration tests.
